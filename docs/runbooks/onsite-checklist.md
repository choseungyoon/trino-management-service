# 사내 배포 · 검증 체크리스트 (이번 회차: 작업 보드 + 벤치마크)

> **이 문서는 순서와 게이트만 갖는다.** 명령의 원본은 각 런북에 있고 여기서 복사하지 않는다 —
> 같은 명령을 두 곳에 적으면 한쪽이 조용히 낡는다. 그게 `BACKLOG.md` 와 부록 B 가 어긋났던 방식이다.
>
> **한 번에 하나씩, 게이트를 통과하고 다음으로 간다.** 위에서 막히면 아래는 볼 필요가 없다.
>
> 상태는 `/work` 보드에 있다. 여기서 체크한 것은 보드에도 반영한다 (`V-7`, `V-8`).

## 0. 이번에 새로 들어가는 것

| | 무엇 | 마이그레이션 | 설정 |
|---|---|---|---|
| **작업 보드** (FR-BOARD) | `/work` — 상태 보드, 요청 접수, 댓글 | `014` `015` | 없음 (항상 켜짐) |
| **벤치마크** (FR-BM-01/03/04) | 쿼리 세트 실행 · 실행 간 비교 | `016` `017` | `benchmark.*` — **기본 꺼짐** |

이전 회차에서 이미 나간 것(리소스 그룹 편집, Fleet, 안전 재시작)은 이 문서가 다루지 않는다. 회귀만 §4 에서 본다.

**오늘 벤치마크를 켜지 않아도 된다.** 보드만 올리고 벤치마크는 다음에 켜도 나머지는 그대로 돈다. 벤치마크는 Gateway 연동과 `ExecuteQuery` 를 함께 요구하므로, 둘 중 하나라도 준비가 안 됐으면 §5 를 통째로 미룬다.

## 6. 새 화면 — 벤치마크 (V-8) `[Gateway + ExecuteQuery 준비된 경우에만]`

### 6-1. 선행

- [ ] `gateway.enabled: true` — **없으면 모든 실행이 거부된다.** 라우팅 상태를 알 수 없는 것은 제외된 상태가 아니다
- [ ] `tms-svc` 에 `ExecuteQuery` 부여 완료 (`executequery-grant.md`)
- [ ] OPA 카탈로그 규칙에서 `tms-svc` 가 데이터 카탈로그에 매칭되지 **않는** 것 재확인 — D-012 의 전제다
- [ ] `benchmark.enabled: true` + `query_sets` 선언 → `tms-api` 재시작

> 쿼리 세트 작성 규칙(읽기 전용, 한 문장, 이름 중복 금지)은 `benchmark.md` §2.
> **잘못 쓰면 기동이 실패한다** — 실행 중에 발견되지 않게 일부러 그렇게 했다.

### 6-2. ⛔ 거부되는 것부터 확인한다

**정상 동작을 먼저 보면 보호 장치가 도는지 알 수 없다.** 운영 중인 클러스터에서:

- [ ] `/clusters/<운영 클러스터>/benchmark` → **빨간 배너**로 거부, 이유가 문장으로 나온다
- [ ] 실행 버튼이 잠겨 있다
- [ ] `curl` 로 폼을 직접 POST 해도 거부된다 (버튼 잠금은 보호 장치가 아니다)

> 여기서 실행이 **되면** 즉시 멈추고 알린다. FR-BM-04 는 타협 불가 항목이다.

### 6-3. 통과 경로

- [ ] 대상 클러스터를 **사람이** 라우팅에서 제외 (Gateway UI 또는 안전 시퀀스 1단계)
- [ ] 실행 중 쿼리가 0 이 될 때까지 대기
- [ ] 벤치마크 화면이 **초록**으로 바뀐다
- [ ] 사유를 적고 실행 → 실행 화면이 5초마다 갱신된다
- [ ] 완료 후 쿼리별 중앙값·최소·CPU 가 채워진다
- [ ] 감사 로그에 `BENCHMARK_RUN` 이 사유와 함께 남았다
- [ ] **중지** 버튼: 다시 실행해서 중지 → 도는 쿼리가 끝난 뒤 `ABORTED`

> **TMS 는 클러스터를 라우팅에서 빼 주지 않는다.** 확인하고 거부만 한다 — 빼 주는 버튼이 있으면
> 그게 곧 안전 시퀀스를 건너뛰는 경로다 (절대규칙 5). 상세: `benchmark.md` §0

### 6-4. 비교 (FR-BM-03)

- [ ] 같은 세트를 **다른 클러스터**에서 한 번 더 실행
- [ ] 실행 화면에서 비교 → 쿼리별 차이와 판정(느려짐/빨라짐/차이 없음)이 나온다
- [ ] 다른 세트의 실행은 **선택지에 안 나온다**

**append-only 확인** (`tms_app`, 둘 다 실패해야 정상)

- [ ] `UPDATE benchmark_result SET elapsed_ms = 1;`
- [ ] `DELETE FROM benchmark_result;`

## 9. 롤백

새 기능 두 개는 **기존 화면과 독립**이다. 문제가 나면 기능만 끄는 것이 먼저다.

| 증상 | 조치 |
|---|---|
| 벤치마크 화면만 문제 | `benchmark.enabled: false` → `tms-api` 재시작. 나머지는 그대로 돈다 |
| 보드 화면만 문제 | 보드는 항상 켜져 있다. DB 를 못 읽으면 화면이 "보드를 읽을 수 없다" 를 표시하고 **다른 화면은 영향받지 않는다** |
| 기존 화면 회귀 | 코드 롤백 (`upgrade-r2-r3.md` §11) |

**마이그레이션은 되돌리지 않는다.** `014`~`017` 은 새 테이블과 감사 액션 하나를 더할 뿐,
기존 테이블의 컬럼을 바꾸지 않는다. 코드를 이전 커밋으로 되돌려도 그 테이블은 그냥 안 쓰일 뿐이다.
